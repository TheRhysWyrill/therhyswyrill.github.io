{% comment %} Ordered review list, built in one pass. Reviews are ordinary top-level pages (this site has no `_reviews` collection), so a single `where` filter returns them. The old version grew the list with `| push` inside a Liquid loop over every page, and each `push` dups the whole array — O(n²) work *per review page*, repeated for all 480 of them, which was the build's single largest cost. (The old version also carried a prev/next loop whose `prev_review`/`next_review` assignments nothing ever read; the footer script computes those itself.) {% endcomment %} {% assign review_pages = site.pages | where: "layout", "review" | sort: "date" %} {% comment %} Written for the Liquid GitHub Pages builds with (4.0.4 via jekyll 3.10), which is stricter than the 4.4.1 used locally: * `where_exp` takes a single comparison — no `and`, no `contains`; * a `for` tag cannot apply a filter to the thing it iterates. Genre matching needs substring containment (`page.genre contains r.genre`), which no `where_exp` grammar expresses, so it is one pass over the candidates ordered newest-first that stops once five are collected: the `push` accumulator never grows past five items, where the old per-review loop copied a ~100-item array on every hit. {% endcomment %} {% assign other_reviews = review_pages | where_exp: "r", "r.url != page.url" %} {% assign candidates = other_reviews | sort: "url" %} {% assign candidate_dates = candidates | group_by_exp: "r", "r.date" | sort: "name" | reverse %} {% assign related_by_genre = "" | split: "," %} {% for day in candidate_dates %} {% if related_by_genre.size >= 5 %}{% break %}{% endif %} {% assign day_items = day.items | sort: "url" %} {% for r in day_items %} {% if related_by_genre.size >= 5 %}{% break %}{% endif %} {% if page.genre and r.genre and page.genre contains r.genre %}{% assign related_by_genre = related_by_genre | push: r %}{% endif %} {% endfor %} {% endfor %} {% if page.platform %} {% assign related_by_platform = other_reviews | where_exp: "r", "r.platform == page.platform" %} {% else %} {% assign related_by_platform = "" | split: "," %} {% endif %} {% comment %} `uniq` drops the reviews matched by both halves. Selection is deterministic: candidates are url-ordered before grouping (Ruby's sort is not stable, and grouping keeps the order it is given), so each date group comes out url-ordered and the newest-first walk is stable when dates tie. {% endcomment %} {% assign related_pool = related_by_genre | concat: related_by_platform | uniq %} {% assign related_reviews = "" | split: "," %} {% assign related_dates = related_pool | group_by_exp: "r", "r.date" | sort: "name" | reverse %} {% for day in related_dates %} {% if related_reviews.size >= 5 %}{% break %}{% endif %} {% assign day_items = day.items | sort: "url" %} {% for r in day_items %} {% if related_reviews.size >= 5 %}{% break %}{% endif %} {% assign related_reviews = related_reviews | push: r %} {% endfor %} {% endfor %} {% if related_reviews.size > 0 %}
